# 시연용 능동 신호 제어

## 제어 기준

Raspberry Pi Relay가 1초마다 받는 `vehicle_count` 최근 5개를 메모리에 보관하고 평균을 계산한다. DB 조회는 제어 경로에 사용하지 않는다.

| 최근 5개 표본 평균 (정상 수신 시 약 5초) | 상태 | 다음 초록불 |
| ---: | --- | ---: |
| 0~6 | 한산 | 5초 |
| 6 초과~11 | 보통 | 10초 |
| 11 초과 | 혼잡 | 15초 |

신호 순서는 `초록 → 노랑 2초 → 빨강 5초 → 초록`이다. 초록불이 시작될 때 가장 최근 5개 평균으로 해당 초록불 길이를 결정하며, 진행 중인 신호를 중간에 단축하지 않는다.

## Bluetooth와 안전 동작

- Pi 장치: `/dev/rfcomm0` (환경변수 `SIGNAL_DEVICE`로 변경 가능)
- UART: 9600 baud, 8N1
- Pi는 현재 색을 1초마다 `SET,1,RED|YELLOW|GREEN` 형식으로 보낸다.
- 유효한 `vehicle_count`가 5개 쌓이기 전에는 빨강을 유지한다.
- 데이터가 10초 넘게 끊기면 평균 버퍼를 비우고 빨강으로 복귀한다.
- STM32는 유효 명령을 5초간 받지 못하면 노랑·초록을 끄고 빨강을 1초 켜짐 / 1초 꺼짐으로 점멸한다. 정상 명령을 다시 받으면 즉시 지정 색으로 돌아간다. 부팅 후 첫 명령이 없는 경우도 동일하다.
- 신호 제어와 Bluetooth 송신은 전용 스레드에서 수행한다. Vision 스레드는 표본 추가만 하고, 짧은 mutex로 최근 5개 표본과 수신 시각을 공유한다. Bluetooth 연결 대기 중에는 mutex를 잡지 않으므로 Vision 수신·Ubuntu 전달을 막지 않는다.
- 장치 쓰기 실패 후 연결을 닫고 재시도하며, 장치를 열 수 없는 동안에는 5초 간격으로 재연결을 시도한다. 장치 열기가 오래 걸린 경우 이전 색을 바로 보내지 않고 최신 데이터로 재판단한다. Bluetooth 대기 중 제어 스레드 자체는 지연될 수 있지만 STM32의 5초 미수신 점멸은 독립적으로 동작한다.
- 차량 데이터 10초 미수신은 정상 빨강 고정, 제어 명령 5초 미수신은 빨강 점멸이다. 서로 다른 장애를 구분한다.

이 기준은 짧은 시간 안에 동작을 보여주기 위한 시연 모드다. 실제 신호 제어 시간과 안전 규정으로 해석하지 않는다.

## 코드 학습 순서

1. `relay_server/src/vision_stream.c`: 차량 수 수신 → 표본 추가 → 신호 제어 호출.
2. `relay_server/src/signal_control.c`: 최근 5개 평균, 단계별 유지 시간, 1초 주기 문자열 송신.
3. `stm32_signal/Core/Src/main.c`의 USER CODE 영역: UART 문자열 수신, LED 선택, 5초 미수신 점멸.
4. `relay_server/src/sync.c`: 센서는 SQLite 저장 후 Ubuntu ACK를 확인한 행만 SENT 처리. 연결 대기는 1초, 개별 송수신 대기는 3초로 제한한다. 실패 시 다음 센서 수신 또는 서버 재시작 때 재시도한다.

핵심 직접 작성 코드에 한글 주석을 넣었다. CubeMX/HAL 자동 생성 부분은 재생성 및 제조사 코드 보존을 위해 수정하지 않는다.
